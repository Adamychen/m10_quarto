Demo — ¿Workflow o agente? Cuánta autonomía necesitas

Procesa tres correos de cliente con cinco patrones, de la cadena simple al agente, y compara llamadas, resultado y previsibilidad.

Demo que acompaña a Patrones de diseño de agentes y prepara el HPD 3 (LangGraph). Se ejecuta en el navegador y no necesita clave de API.

NoteLas ejecuciones son simuladas

No hay ningún LLM detrás: cada recorrido está escrito a mano para ilustrar cómo se comporta cada patrón. Las cifras de llamadas y tiempos son orientativas (unos 1,5 s por llamada al LLM).

Una tienda online recibe correos de clientes y quiere responderlos con un LLM. Hay muchas formas de montar el sistema, desde una sola llamada hasta un agente que decide por sí mismo qué hacer. Más autonomía no siempre es mejor: cuesta más llamadas, más tiempo y es menos predecible.

Elige un correo y un patrón. El diagrama marca el camino que sigue el correo; abajo, la tabla compara los cinco patrones con ese mismo correo.

def case(p, e, run=0):
    """Ejecución de un patrón sobre un correo (para el agente, la variante `run`)."""
    if p != "agente":
        return CASES[(p, e)]
    r = AGENT_RUNS[e][run]
    calls = len(r["tools"]) + 1  # una decisión por herramienta y otra para responder
    trace = [("in", "Llega el correo.")]
    for t in r["tools"]:
        trace += [("llm", f"Decide usar <code>{t}</code>."), ("tools", f"Ejecuta <code>{t}</code> y devuelve el resultado.")]
    trace += [("llm", "Decide que ya puede responder."), ("out", r["answer"])]
    notes = {OK: "Lo resuelve, decidiendo él mismo qué consultar.",
             PARTIAL: "Esta vez se para antes de tiempo: el agente decide cuándo ha terminado, y a veces se equivoca."}
    return dict(calls=calls, secs=1.55 * calls, result=r["result"], trace=trace, note=notes[r["result"]],
                loops=len(r["tools"]))

email = reactive.value(1)
pattern = reactive.value("encadenado")
runs = reactive.value([])
agent_run = reactive.value(0)


@reactive.effect
@reactive.event(input.pick_email)
def _pe():
    email.set(int(input.pick_email()))
    runs.set([])
    agent_run.set(0)


@reactive.effect
@reactive.event(input.pick_pat)
def _pp():
    pattern.set(input.pick_pat())
    runs.set([])
    agent_run.set(0)


@reactive.effect
@reactive.event(input.run5)
def _run5():
    p, e = pattern(), email()
    if p == "agente":
        idx = [random.randrange(len(AGENT_RUNS[e])) for _ in range(5)]
        agent_run.set(idx[-1])
        runs.set([case(p, e, i) for i in idx])
    else:
        runs.set([case(p, e)] * 5)

def graph(p, path, loops):
    P = PATTERNS[p]
    nodes, visited = P["nodes"], set(path)
    order = {}
    for i, n in enumerate(path):
        order.setdefault(n, i + 1)
    parts = ["<defs><marker id='ar' viewBox='0 0 10 10' refX='9' refY='5' markerWidth='6' markerHeight='6' "
             "orient='auto'><path d='M0,0 L10,5 L0,10 z' fill='#6b7280'/></marker>"
             "<marker id='arh' viewBox='0 0 10 10' refX='9' refY='5' markerWidth='6' markerHeight='6' "
             "orient='auto'><path d='M0,0 L10,5 L0,10 z' fill='#e65100'/></marker></defs>"]
    used = {(path[i], path[i + 1]) for i in range(len(path) - 1)}
    if p == "paralelo":
        used |= {("in", n) for n in ("env", "cob", "rdv")} | {(n, "agg") for n in ("env", "cob", "rdv")}
    W = P.get("w", 52)
    for a, b in P["edges"]:
        (x1, y1, *_), (x2, y2, *_) = nodes[a], nodes[b]
        on = (a, b) in used
        dy = 0
        if p == "agente" and {a, b} == {"llm", "tools"}:
            dy = -8 if a == "llm" else 8
        sx, sy = x1 + (W if x2 > x1 else -W if x2 < x1 else 0), y1 + dy
        ex, ey = x2 - (W if x2 > x1 else -W if x2 < x1 else 0), y2 + dy
        parts.append(
            f"<line x1='{sx}' y1='{sy}' x2='{ex}' y2='{ey}' stroke='{ORANGE if on else '#d1d5db'}' "
            f"stroke-width='{2.6 if on else 1.4}' marker-end='url(#{'arh' if on else 'ar'})'/>"
        )
    for n, (x, y, label, kind) in nodes.items():
        fill, tc = KIND[kind]
        on = n in visited
        words = label.split(" ")
        lines = [" ".join(words[: (len(words) + 1) // 2]), " ".join(words[(len(words) + 1) // 2:])] \
            if len(label) > 13 else [label]
        text = "".join(
            f"<tspan x='{x}' dy='{0 if i == 0 else 13}'>{l}</tspan>" for i, l in enumerate(lines))
        ty = y + 4 - 6 * (len(lines) - 1)
        parts.append(
            f"<g opacity='{1 if on else 0.3}'><rect x='{x - W}' y='{y - 22}' width='{2 * W}' height='44' rx='9' "
            f"fill='{fill}' stroke='{'#111' if on else 'none'}' stroke-width='1.5'/>"
            f"<text x='{x}' y='{ty}' text-anchor='middle' font-size='12' font-weight='600' fill='{tc}'>{text}</text></g>"
        )
        if n in order:
            parts.append(

Qué observar

  1. Correo de Lucía (pregunta sencilla). La cadena simple lo resuelve con una llamada. Todo lo demás también funciona, pero gasta de dos a cuatro veces más. La tabla marca la cadena simple como «la más simple que lo resuelve».
  2. Correo de Marcos (devolución). La cadena simple suena bien, pero no comprueba el pedido: promete algo que nadie ha verificado. El encadenado es el caso ideal: siempre los mismos pasos, con los datos reales del pedido.
  3. Correo de Elena (dos problemas). El encadenado y el enrutado resuelven solo uno: están diseñados para un tipo de problema por correo. La paralelización resuelve los dos sin agente, porque tiene un revisor para cada tipo de problema. El agente también lo resuelve.
  4. Con el agente seleccionado, pulsa «Ejecutar 5 veces». Cambian las llamadas y, a veces, el resultado: el agente decide cuándo ha terminado y en ocasiones se para antes de tiempo. Repite con un workflow: cinco ejecuciones idénticas.

Qué has visto

  • Empieza por lo más simple que funcione. La tabla de cada correo responde a la pregunta «¿hace falta un agente?». En dos de los tres correos, no.
  • Los workflows (el código decide el orden) son predecibles, baratos y fáciles de probar. Funcionan cuando conoces la estructura de la tarea, y fallan cuando llega algo para lo que no se diseñaron.
  • Un agente se adapta a lo imprevisto, pero cada ejecución es distinta: más difícil de probar, de depurar y de presupuestar.
  • A menudo un workflow bien diseñado (aquí, la paralelización) cubre el caso difícil sin ceder el control al LLM.

## Las ejecuciones son simuladas

No hay ningún LLM detrás: cada recorrido está escrito a mano para ilustrar cómo se comporta cada patrón. Las cifras de llamadas y tiempos son orientativas (unos 1,5 s por llamada al LLM).

Una tienda online recibe correos de clientes y quiere responderlos con un LLM. Hay muchas formas de montar el sistema, desde una sola llamada hasta un agente que decide por sí mismo qué hacer. **Más autonomía no siempre es mejor**: cuesta más llamadas, más tiempo y es menos predecible.

Elige un correo y un patrón. El diagrama marca el camino que sigue el correo; abajo, la tabla compara los cinco patrones con ese mismo correo.

def case(p, e, run=0):
    """Ejecución de un patrón sobre un correo (para el agente, la variante `run`)."""
    if p != "agente":
        return CASES[(p, e)]
    r = AGENT_RUNS[e][run]
    calls = len(r["tools"]) + 1  # una decisión por herramienta y otra para responder
    trace = [("in", "Llega el correo.")]
    for t in r["tools"]:
        trace += [("llm", f"Decide usar <code>{t}</code>."), ("tools", f"Ejecuta <code>{t}</code> y devuelve el resultado.")]
    trace += [("llm", "Decide que ya puede responder."), ("out", r["answer"])]
    notes = {OK: "Lo resuelve, decidiendo él mismo qué consultar.",
             PARTIAL: "Esta vez se para antes de tiempo: el agente decide cuándo ha terminado, y a veces se equivoca."}
    return dict(calls=calls, secs=1.55 * calls, result=r["result"], trace=trace, note=notes[r["result"]],
                loops=len(r["tools"]))

def graph(p, path, loops):
    P = PATTERNS[p]
    nodes, visited = P["nodes"], set(path)
    order = {}
    for i, n in enumerate(path):
        order.setdefault(n, i + 1)
    parts = ["<defs><marker id='ar' viewBox='0 0 10 10' refX='9' refY='5' markerWidth='6' markerHeight='6' "
             "orient='auto'><path d='M0,0 L10,5 L0,10 z' fill='#6b7280'/></marker>"
             "<marker id='arh' viewBox='0 0 10 10' refX='9' refY='5' markerWidth='6' markerHeight='6' "
             "orient='auto'><path d='M0,0 L10,5 L0,10 z' fill='#e65100'/></marker></defs>"]
    used = {(path[i], path[i + 1]) for i in range(len(path) - 1)}
    if p == "paralelo":
        used |= {("in", n) for n in ("env", "cob", "rdv")} | {(n, "agg") for n in ("env", "cob", "rdv")}
    W = P.get("w", 52)
    for a, b in P["edges"]:
        (x1, y1, *_), (x2, y2, *_) = nodes[a], nodes[b]
        on = (a, b) in used
        dy = 0
        if p == "agente" and {a, b} == {"llm", "tools"}:
            dy = -8 if a == "llm" else 8
        sx, sy = x1 + (W if x2 > x1 else -W if x2 < x1 else 0), y1 + dy
        ex, ey = x2 - (W if x2 > x1 else -W if x2 < x1 else 0), y2 + dy
        parts.append(
            f"<line x1='{sx}' y1='{sy}' x2='{ex}' y2='{ey}' stroke='{ORANGE if on else '#d1d5db'}' "
            f"stroke-width='{2.6 if on else 1.4}' marker-end='url(#{'arh' if on else 'ar'})'/>"
        )
    for n, (x, y, label, kind) in nodes.items():
        fill, tc = KIND[kind]
        on = n in visited
        words = label.split(" ")
        lines = [" ".join(words[: (len(words) + 1) // 2]), " ".join(words[(len(words) + 1) // 2:])] \
            if len(label) > 13 else [label]
        text = "".join(
            f"<tspan x='{x}' dy='{0 if i == 0 else 13}'>{l}</tspan>" for i, l in enumerate(lines))
        ty = y + 4 - 6 * (len(lines) - 1)
        parts.append(
            f"<g opacity='{1 if on else 0.3}'><rect x='{x - W}' y='{y - 22}' width='{2 * W}' height='44' rx='9' "
            f"fill='{fill}' stroke='{'#111' if on else 'none'}' stroke-width='1.5'/>"
            f"<text x='{x}' y='{ty}' text-anchor='middle' font-size='12' font-weight='600' fill='{tc}'>{text}</text></g>"
        )
        if n in order:
            parts.append(
                f"<circle cx='{x + W - 4}' cy='{y - 22}' r='9' fill='#fff' stroke='#111'/>"
                f"<text x='{x + W - 4}' y='{y - 18}' text-anchor='middle' font-size='10' font-weight='700'>{order[n]}</text>"
            )
    if p == "agente" and loops:
        parts.append(
            f"<text x='440' y='8' text-anchor='middle' font-size='12' font-weight='700' fill='{ORANGE}'>"
            f"↻ {loops} vuelta{'s' if loops != 1 else ''}</text>")
    ys = [y for (_, y, *_) in nodes.values()]
    top, bottom = min(ys) - 34, max(ys) + 30
    if p == "agente":
        top = -8
    legend = "".join(
        f"<rect x='{20 + i * 150}' y='{bottom + 4}' width='12' height='12' rx='3' fill='{KIND[k][0]}'/>"
        f"<text x='{38 + i * 150}' y='{bottom + 14}' font-size='11' fill='#374151'>{t}</text>"
        for i, (k, t) in enumerate([("llm", "llamada al LLM"), ("code", "código normal"),
                                    ("tool", "herramientas"), ("io", "entrada / salida")])
    )
    return (f"<svg viewBox='0 {top} 640 {bottom - top + 22}' width='100%' "
            f"style='display:block;max-width:680px;margin:6px auto' "
            f"font-family='system-ui,sans-serif'>{''.join(parts)}{legend}</svg>")

## Qué observar

1. **Correo de Lucía (pregunta sencilla).** La cadena simple lo resuelve con una llamada. Todo lo demás también funciona, pero gasta de dos a cuatro veces más. La tabla marca la cadena simple como «la más simple que lo resuelve».
2. **Correo de Marcos (devolución).** La cadena simple suena bien, pero no comprueba el pedido: promete algo que nadie ha verificado. El **encadenado** es el caso ideal: siempre los mismos pasos, con los datos reales del pedido.
3. **Correo de Elena (dos problemas).** El encadenado y el enrutado resuelven solo uno: están diseñados para un tipo de problema por correo. La **paralelización** resuelve los dos *sin agente*, porque tiene un revisor para cada tipo de problema. El agente también lo resuelve.
4. Con el **agente** seleccionado, pulsa **«Ejecutar 5 veces»**. Cambian las llamadas y, a veces, el resultado: el agente decide cuándo ha terminado y en ocasiones se para antes de tiempo. Repite con un workflow: cinco ejecuciones idénticas.

## Qué has visto

- **Empieza por lo más simple que funcione.** La tabla de cada correo responde a la pregunta «¿hace falta un agente?». En dos de los tres correos, no.
- Los **workflows** (el código decide el orden) son predecibles, baratos y fáciles de probar. Funcionan cuando conoces la estructura de la tarea, y fallan cuando llega algo para lo que no se diseñaron.
- Un **agente** se adapta a lo imprevisto, pero cada ejecución es distinta: más difícil de probar, de depurar y de presupuestar.
- A menudo un workflow bien diseñado (aquí, la paralelización) cubre el caso difícil sin ceder el control al LLM.
