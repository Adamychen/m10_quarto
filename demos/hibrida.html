Demo — Búsqueda híbrida: palabras, significado y fusión

Compara lado a lado la búsqueda por palabras (BM25), por significado (embeddings) y su fusión (RRF) sobre las mismas consultas, y comprueba cuál deja más veces la respuesta al alcance del LLM.

Demo que acompaña a Recuperación. Usa el mismo FAQ, el mismo BM25 y el mismo modelo de embeddings (paraphrase-multilingual-MiniLM-L12-v2) que el capítulo, así que obtendrás los mismos rankings en el notebook. Los embeddings se calcularon una vez y se guardaron como datos estáticos; BM25 se calcula en tu navegador. No necesitas clave de API.

Hay dos formas de buscar en una colección de documentos: por palabras (BM25 cuenta qué palabras de la consulta aparecen en cada documento) y por significado (los embeddings comparan de qué trata cada texto). La búsqueda híbrida las combina con Reciprocal Rank Fusion (RRF): ignora las puntuaciones y suma solo los puestos de cada documento en los dos rankings.

Elige una consulta y mira dónde queda la respuesta correcta (en verde) en cada columna. Después mueve el peso de la fusión y vigila el marcador.

# ── BM25: el mismo código que en bloque1/01e-recuperacion.qmd ────────────────
PALABRAS_VACIAS = set("el la los las un una unos unas de del al a en y o que qué me mi tu te se es por con para si su sus lo como cuánto cuál cómo cada".split())


def tokenizar(texto):
    palabras = re.findall(r"[a-záéíóúñü0-9\-]+", texto.lower())
    return [p for p in palabras if p not in PALABRAS_VACIAS]


class BM25:
    def __init__(self, documentos, k1=1.5, b=0.75):
        self.docs = [tokenizar(d) for d in documentos]
        self.k1, self.b = k1, b
        self.N = len(self.docs)
        self.avgdl = sum(len(d) for d in self.docs) / self.N
        self.df = Counter(p for d in self.docs for p in set(d))

    def idf(self, palabra):
        return math.log(1 + (self.N - self.df[palabra] + 0.5) / (self.df[palabra] + 0.5))

    def puntuaciones(self, consulta):
        resultado = [0.0] * self.N
        for i, doc in enumerate(self.docs):
            frecuencias = Counter(doc)
            for p in tokenizar(consulta):
                if p in frecuencias:
                    f = frecuencias[p]
                    norm = f + self.k1 * (1 - self.b + self.b * len(doc) / self.avgdl)
                    resultado[i] += self.idf(p) * f * (self.k1 + 1) / norm
        return resultado


bm25 = BM25(DOCS)


def rankings(qi, w):
    """Rankings léxico, denso e híbrido (RRF ponderado) con sus puntuaciones."""
    Q = QUERIES[qi]
    b = bm25.puntuaciones(Q["q"])
    lex = [j for j in sorted(range(len(DOCS)), key=lambda j: -b[j]) if b[j] > 0]
    den = sorted(range(len(DOCS)), key=lambda j: -Q["cos"][j])
    rrf = Counter()
    for weight, rk in ((w, lex), (1 - w, den)):
        for pos, j in enumerate(rk, start=1):
            rrf[j] += weight / (C + pos)
    hyb = [j for j in sorted(rrf, key=lambda j: -rrf[j]) if rrf[j] > 0]
    return {"lex": (lex, b), "den": (den, Q["cos"]), "hyb": (hyb, rrf)}


def place(R, key, j):
    """Puesto de j con empates compartidos (1 + documentos con puntuación estrictamente mayor)."""
    rk, sc = R[key]
    if j not in rk:
        return None
    return 1 + sum(1 for i in rk if sc[i] > sc[j] + 1e-12)


def tied(R, key, j):
    rk, sc = R[key]
    return j in rk and sum(1 for i in rk if abs(sc[i] - sc[j]) < 1e-12) > 1

def columns():
    k, w = sel(), input.w()
    gold = QUERIES[k]["gold"]
    R = rankings(k, 1 - w)  # el deslizador va de palabras (0) a significado (1)
    W, colw, rowh, top = 820, 230, 44, 58
    xs = {"lex": 10, "hyb": (W - colw) / 2, "den": W - colw - 10}
    titles = {"lex": "Palabras (BM25)", "hyb": "Fusión (RRF)", "den": "Significado (embeddings)"}
    colors = {"lex": ORANGE, "hyb": DARK, "den": BLUE}
    parts = []
    # Pesos de cada método en la fusión, dibujados como grosor de la cabecera
    weights = {"lex": 1 - w, "den": w}
    pos = {}
    for key in ("lex", "hyb", "den"):
        rk, _ = R[key]
        pos[key] = {j: i for i, j in enumerate(rk[:TOP])}
    # Líneas: del puesto en cada método al puesto en la fusión
    for side in ("lex", "den"):
        for j, i in pos[side].items():
            if j not in pos["hyb"]:

            h = pos["hyb"][j]
            x1 = xs[side] + (colw if side == "lex" else 0)
            x2 = xs["hyb"] + (0 if side == "lex" else colw)

            is_gold = j == gold
            op = 0.15 + 0.85 * weights[side]

                f"stroke-opacity='{op:.2f}'/>"

    for key in ("lex", "hyb", "den"):

        parts.append(

            parts.append(

            y = top + i * rowh
            is_gold = j == gold
            bar = colw - 54

@render.ui
def scoreboard():
    w = input.w()
    hits = {"lex": 0, "den": 0, "hyb": 0}
    for i, Q in enumerate(QUERIES):
        R = rankings(i, 1 - w)
        for key in hits:
            p = place(R, key, Q["gold"])
            if p is not None and p <= K:
                hits[key] += 1
    n = len(QUERIES)
    best = max(hits.values())

    def tile(key, name, color):
        star = " ★" if hits[key] == best else ""
        return (f"<div class='tile'><span class='muted'>{name}</span>"
                f"<b style='color:{color}'>{hits[key]} de {n}{star}</b></div>")

    return ui.HTML(
        f"<div class='card'><b>Marcador: ¿en cuántas consultas entra la respuesta correcta entre las {K} primeras?</b> "
        f"<div class='muted'>En un RAG, esas {K} son las que se le pasan al LLM: si la respuesta queda fuera, "
        f"el modelo no la verá. Cuenta las {n} consultas con el peso actual.</div>"
        f"<div class='board' style='margin-top:6px'>{tile('lex', 'Palabras (BM25)', ORANGE)}"
        f"{tile('den', 'Significado (embeddings)', BLUE)}{tile('hyb', 'Fusión (RRF)', DARK)}</div></div>"
    )

        style = f" style='color:{GREEN};font-weight:700'" if j == gold else ""
        rows.append(f"<tr{style}><td>{html.escape(LABELS[j])}</td><td>{a}</td><td>{b}</td><td>{rrf[j]:.4f}</td></tr>")
    return ui.HTML(
        "<div class='card' style='overflow-x:auto'><table class='nums'><thead><tr><th>Documento</th>"
        "<th>Palabras</th><th>Significado</th><th>Total</th></tr></thead>"
        f"<tbody>{''.join(rows)}</tbody></table><p class='muted' style='margin:6px 0 0'>"
        "Cada método aporta peso / (60 + puesto). Solo cuentan los puestos, no las puntuaciones: "
        "por eso se pueden sumar un BM25 (de 0 a decenas) y un coseno (de 0 a 1). "
        "Con peso 0,5 da el mismo orden que la RRF estándar del capítulo (con los números a la mitad).</p></div>"
    )

Qué observar

  1. Consulta 1 (Euríbor). BM25 lo encuentra al instante: es un nombre propio y está escrito tal cual. Los embeddings lo dejan en el puesto 5, fuera de lo que leería el LLM. La fusión lo pone primero: le basta con que un método lo vea.
  2. Consulta 2 (clave de acceso). La columna de palabras está vacía: el documento dice «contraseña» y no hay ninguna palabra en común. Los embeddings la encuentran a la primera, y la fusión también.
  3. Consulta 3 (error E-4012). Los dos métodos se contradicen exactamente: uno pone E-4012 primero y E-4021 segundo, y el otro al revés. En la fusión suman lo mismo y quedan empatados. Activa «Ver los números» para comprobarlo.
  4. Consulta 4 (límite para pagar con tarjeta). «Pagar» y «tarjeta» aparecen en muchos documentos, así que BM25 entierra la respuesta en el puesto 5. La fusión no la pone primera, pero la deja segunda, dentro de las tres que leería el LLM.
  5. Mira el marcador con peso 50 %: la respuesta entra entre las 3 primeras en 2 de 4 consultas con palabras, 3 de 4 con significado y 4 de 4 con la fusión. Lleva el deslizador a un extremo y la fusión se convierte en ese método por separado, con sus mismos fallos.

Qué has visto

  • Cada método falla donde el otro acierta. Las palabras aciertan con nombres propios, códigos y términos exactos; el significado, con sinónimos y paráfrasis.
  • La fusión no es más lista que cada método: es más segura. No siempre pone la respuesta la primera, e incluso puede empatar, pero casi nunca la deja fuera de los documentos que recibe el LLM. En un RAG, eso es lo que importa.
  • Cuál es mejor depende de las preguntas. Por eso, en un RAG real, se mide con un conjunto de preguntas de referencia, como en la sección de métricas.
WarningQué es real y qué está simplificado
  • Los rankings son reales: BM25 y embeddings calculados sobre el FAQ del capítulo. Las cuatro consultas se eligieron para que cada una muestre un caso con claridad, entre unas sesenta probadas. Con muchas otras los dos métodos coinciden y no hay nada que fusionar.
  • El FAQ tiene 14 documentos. En una colección grande hay muchos más candidatos parecidos y las diferencias entre métodos son más frecuentes.
  • Con solo dos rankings, los empates exactos en la fusión son habituales (basta con que los métodos intercambien sus dos primeros puestos). Cada implementación los deshace a su manera; aquí se muestran tal cual.

> Demo que acompaña a [Recuperación](../bloque1/01e-recuperacion.qmd#sec-hibrida). Usa el mismo FAQ, el mismo BM25 y el mismo modelo de embeddings (`paraphrase-multilingual-MiniLM-L12-v2`) que el capítulo, así que obtendrás los mismos rankings en el notebook. Los embeddings se calcularon una vez y se guardaron como datos estáticos; BM25 se calcula en tu navegador. No necesitas clave de API.

Hay dos formas de buscar en una colección de documentos: por **palabras** (BM25 cuenta qué palabras de la consulta aparecen en cada documento) y por **significado** (los embeddings comparan de qué trata cada texto). La **búsqueda híbrida** las combina con *Reciprocal Rank Fusion* (RRF): ignora las puntuaciones y suma solo los puestos de cada documento en los dos rankings.

Elige una consulta y mira dónde queda la respuesta correcta (en verde) en cada columna. Después mueve el peso de la fusión y vigila el marcador.

PALABRAS_VACIAS = set("el la los las un una unos unas de del al a en y o que qué me mi tu te se es por con para si su sus lo como cuánto cuál cómo cada".split())


def tokenizar(texto):
    palabras = re.findall(r"[a-záéíóúñü0-9\-]+", texto.lower())
    return [p for p in palabras if p not in PALABRAS_VACIAS]


class BM25:
    def __init__(self, documentos, k1=1.5, b=0.75):
        self.docs = [tokenizar(d) for d in documentos]
        self.k1, self.b = k1, b
        self.N = len(self.docs)
        self.avgdl = sum(len(d) for d in self.docs) / self.N
        self.df = Counter(p for d in self.docs for p in set(d))

    def idf(self, palabra):
        return math.log(1 + (self.N - self.df[palabra] + 0.5) / (self.df[palabra] + 0.5))

    def puntuaciones(self, consulta):
        resultado = [0.0] * self.N
        for i, doc in enumerate(self.docs):
            frecuencias = Counter(doc)
            for p in tokenizar(consulta):
                if p in frecuencias:
                    f = frecuencias[p]
                    norm = f + self.k1 * (1 - self.b + self.b * len(doc) / self.avgdl)
                    resultado[i] += self.idf(p) * f * (self.k1 + 1) / norm
        return resultado


bm25 = BM25(DOCS)


def rankings(qi, w):
    """Rankings léxico, denso e híbrido (RRF ponderado) con sus puntuaciones."""
    Q = QUERIES[qi]
    b = bm25.puntuaciones(Q["q"])
    lex = [j for j in sorted(range(len(DOCS)), key=lambda j: -b[j]) if b[j] > 0]
    den = sorted(range(len(DOCS)), key=lambda j: -Q["cos"][j])
    rrf = Counter()
    for weight, rk in ((w, lex), (1 - w, den)):
        for pos, j in enumerate(rk, start=1):
            rrf[j] += weight / (C + pos)
    hyb = [j for j in sorted(rrf, key=lambda j: -rrf[j]) if rrf[j] > 0]
    return {"lex": (lex, b), "den": (den, Q["cos"]), "hyb": (hyb, rrf)}


def place(R, key, j):
    """Puesto de j con empates compartidos (1 + documentos con puntuación estrictamente mayor)."""
    rk, sc = R[key]
    if j not in rk:
        return None
    return 1 + sum(1 for i in rk if sc[i] > sc[j] + 1e-12)


def tied(R, key, j):
    rk, sc = R[key]
    return j in rk and sum(1 for i in rk if abs(sc[i] - sc[j]) < 1e-12) > 1

## Qué observar

1. **Consulta 1 (Euríbor).** BM25 lo encuentra al instante: es un nombre propio y está escrito tal cual. Los embeddings lo dejan en el puesto 5, fuera de lo que leería el LLM. La fusión lo pone primero: le basta con que un método lo vea.
2. **Consulta 2 (clave de acceso).** La columna de palabras está vacía: el documento dice «contraseña» y no hay ninguna palabra en común. Los embeddings la encuentran a la primera, y la fusión también.
3. **Consulta 3 (error E-4012).** Los dos métodos se contradicen exactamente: uno pone E-4012 primero y E-4021 segundo, y el otro al revés. En la fusión suman lo mismo y quedan **empatados**. Activa «Ver los números» para comprobarlo.
4. **Consulta 4 (límite para pagar con tarjeta).** «Pagar» y «tarjeta» aparecen en muchos documentos, así que BM25 entierra la respuesta en el puesto 5. La fusión no la pone primera, pero la deja segunda, dentro de las tres que leería el LLM.
5. Mira el **marcador** con peso 50 %: la respuesta entra entre las 3 primeras en 2 de 4 consultas con palabras, 3 de 4 con significado y **4 de 4 con la fusión**. Lleva el deslizador a un extremo y la fusión se convierte en ese método por separado, con sus mismos fallos.

## Qué has visto

- **Cada método falla donde el otro acierta.** Las palabras aciertan con nombres propios, códigos y términos exactos; el significado, con sinónimos y paráfrasis.
- **La fusión no es más lista que cada método: es más segura.** No siempre pone la respuesta la primera, e incluso puede empatar, pero casi nunca la deja fuera de los documentos que recibe el LLM. En un RAG, eso es lo que importa.

## Qué es real y qué está simplificado

- Los rankings son **reales**: BM25 y embeddings calculados sobre el FAQ del capítulo. Las cuatro consultas se **eligieron** para que cada una muestre un caso con claridad, entre unas sesenta probadas. Con muchas otras los dos métodos coinciden y no hay nada que fusionar.
- El FAQ tiene 14 documentos. En una colección grande hay muchos más candidatos parecidos y las diferencias entre métodos son más frecuentes.
- Con solo dos rankings, los empates exactos en la fusión son habituales (basta con que los métodos intercambien sus dos primeros puestos). Cada implementación los deshace a su manera; aquí se muestran tal cual.
