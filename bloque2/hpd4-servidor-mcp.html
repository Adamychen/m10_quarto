HPD 4 — Servidor MCP y conexión segura a datos locales

Competencias: CE-3

TipObjetivos
  • Implementar un servidor MCP con FastMCP que exponga datos de facturación
  • Definir herramientas (tools) y recursos (resources) tipados con Python
  • Conectar un cliente LLM y dejar que decida qué tool usar
  • Aplicar y probar medidas de seguridad (solo lectura, sanitización, límites)
  • Analizar riesgos: prompt injection, data leakage

Materiales

  • Librerías: fastmcp, sqlite3 (stdlib), openai, python-dotenv
  • Base de datos SQLite de ejemplo: Chinook (tienda de música digital, se descarga en el notebook)
  • LLM: API Llamus US (https://llamus.cs.us.es/api/v1) o local (Ollama)

Pipeline

  1. Setup: descargar la base Chinook y abrirla en modo solo lectura
  2. Servidor: implementar tools y resources con FastMCP
  3. Cliente: conectar un LLM y probar consultas en lenguaje natural
  4. Seguridad: sanitización, límites, test de ataques
  5. Evaluación: batería de preguntas y análisis de riesgos
Note¿Por qué necesitas esto?

Imagina que trabajas como analista en una empresa con 3 sistemas distintos: un ERP con la facturación, un CRM con clientes y hojas de cálculo con inventario. Conectar un asistente conversacional a cada uno requeriría 3 integraciones distintas, cada una con su propia autenticación y formato. MCP (Model Context Protocol) resuelve esto: es un estándar abierto que actúa como un USB-C para LLM. Defines un servidor por cada fuente de datos y cualquier cliente LLM se conecta igual.

En este taller construyes tu primer servidor MCP sobre una base de datos real de ejemplo (Chinook, con facturas, clientes, catálogo y empleados). La arquitectura escala a cualquier fuente de datos: SQL, APIs REST, archivos locales, servicios cloud. El protocolo es el mismo.

1.1 Descargar y abrir la base Chinook

Chinook es una base de datos de ejemplo de una tienda de música digital: catálogo (artistas, álbumes, pistas, géneros), clientes, empleados y facturas. Fue creada por Luis Rocha y se distribuye con licencia MIT. Los datos de catálogo proceden de una biblioteca de iTunes real; clientes y empleados son ficticios.

El fichero SQLite pesa unos 1 MB. Lo descargamos una vez, lo guardamos en caché en el directorio temporal y lo abrimos en modo solo lectura (mode=ro): el servidor MCP nunca debe poder modificar los datos.

CHINOOK_URL = "https://github.com/lerocha/chinook-database/raw/master/ChinookDatabase/DataSources/Chinook_Sqlite.sqlite"
CHINOOK_PATH = os.path.join(tempfile.gettempdir(), "chinook_cache", "Chinook_Sqlite.sqlite")

def _es_chinook(path) -> bool:
    """Comprueba que el fichero es SQLite y contiene la tabla Invoice."""
    try:
        con = sqlite3.connect(f"{Path(path).resolve().as_uri()}?mode=ro", uri=True)
        try:
            return con.execute(
                "SELECT 1 FROM sqlite_master WHERE type='table' AND name='Invoice'"
            ).fetchone() is not None
        finally:
            con.close()
    except sqlite3.DatabaseError:
        return False

def descargar_chinook(url=CHINOOK_URL, destino=CHINOOK_PATH, timeout=60) -> str:
    """Descarga Chinook (~1 MB) al directorio temporal. Si ya existe la copia en caché, no la descarga de nuevo."""
    if os.path.exists(destino) and _es_chinook(destino):
        return destino
    os.makedirs(os.path.dirname(destino), exist_ok=True)
    tmp = destino + ".part"
    try:
        with urllib.request.urlopen(url, timeout=timeout) as resp:
            data = resp.read()
        with open(tmp, "wb") as f:
            f.write(data)
    except Exception as e:
        raise RuntimeError(
            f"No se pudo descargar la base Chinook desde:\n  {url}\n"
            f"Causa: {e}\n"
            "Comprueba la conexión a Internet. Si el problema persiste, descarga el fichero "
            f"manualmente y guárdalo en:\n  {destino}"
        ) from e
    if not _es_chinook(tmp):
        os.remove(tmp)
        raise RuntimeError("El fichero descargado no es la base Chinook (SQLite con tabla Invoice).")
    os.replace(tmp, destino)
    return destino

def conectar_solo_lectura(path: str):
    """Abre la base en modo solo lectura (mode=ro) y con un autorizador que solo permite leer:
    el motor rechaza ATTACH, PRAGMA, escrituras y cualquier otra acción aunque el validador falle."""
    uri = Path(path).resolve().as_uri() + "?mode=ro"
    con = sqlite3.connect(uri, uri=True, check_same_thread=False)
    permitidas = {sqlite3.SQLITE_SELECT, sqlite3.SQLITE_READ, sqlite3.SQLITE_FUNCTION}
    con.set_authorizer(lambda accion, *_: sqlite3.SQLITE_OK if accion in permitidas else sqlite3.SQLITE_DENY)
    return con

4.2 Función de consulta al servidor MCP

Como el servidor MCP se comunica por stdio (no por HTTP), no podemos llamarlo directamente desde el notebook sin lanzarlo como subproceso. Para simplificar la sesión presencial, vamos a simular la conexión cliente-servidor invocando las tools de FastMCP directamente (equivalente funcional).

Note¿Por qué simulamos la conexión?

En producción, el cliente LLM lanza el servidor MCP como subproceso y se comunica por stdin/stdout. Pero en un notebook de Colab, lanzar subprocesos es complejo. Llamar a las tools directamente produce exactamente el mismo resultado y nos permite centrarnos en lo importante: ver cómo el LLM decide qué tool usar.

El fichero SQLite pesa unos 1 MB. Lo descargamos una vez, lo guardamos en caché en el directorio temporal y lo abrimos en **modo solo lectura** (`mode=ro`): el servidor MCP nunca debe poder modificar los datos.

```{python}
#| echo: true

CHINOOK_URL = "https://github.com/lerocha/chinook-database/raw/master/ChinookDatabase/DataSources/Chinook_Sqlite.sqlite"
CHINOOK_PATH = os.path.join(tempfile.gettempdir(), "chinook_cache", "Chinook_Sqlite.sqlite")

def _es_chinook(path) -> bool:
    """Comprueba que el fichero es SQLite y contiene la tabla Invoice."""
    try:
        con = sqlite3.connect(f"{Path(path).resolve().as_uri()}?mode=ro", uri=True)
        try:
            return con.execute(
                "SELECT 1 FROM sqlite_master WHERE type='table' AND name='Invoice'"
            ).fetchone() is not None
        finally:
            con.close()
    except sqlite3.DatabaseError:
        return False

def descargar_chinook(url=CHINOOK_URL, destino=CHINOOK_PATH, timeout=60) -> str:
    """Descarga Chinook (~1 MB) al directorio temporal. Si ya existe la copia en caché, no la descarga de nuevo."""
    if os.path.exists(destino) and _es_chinook(destino):
        return destino
    os.makedirs(os.path.dirname(destino), exist_ok=True)
    tmp = destino + ".part"
    try:
        with urllib.request.urlopen(url, timeout=timeout) as resp:
            data = resp.read()
        with open(tmp, "wb") as f:
            f.write(data)
    except Exception as e:
        raise RuntimeError(
            f"No se pudo descargar la base Chinook desde:\n  {url}\n"
            f"Causa: {e}\n"
            "Comprueba la conexión a Internet. Si el problema persiste, descarga el fichero "
            f"manualmente y guárdalo en:\n  {destino}"
        ) from e
    if not _es_chinook(tmp):
        os.remove(tmp)
        raise RuntimeError("El fichero descargado no es la base Chinook (SQLite con tabla Invoice).")
    os.replace(tmp, destino)
    return destino

def conectar_solo_lectura(path: str):
    """Abre la base en modo solo lectura (mode=ro) y con un autorizador que solo permite leer:
    el motor rechaza ATTACH, PRAGMA, escrituras y cualquier otra acción aunque el validador falle."""
    uri = Path(path).resolve().as_uri() + "?mode=ro"
    con = sqlite3.connect(uri, uri=True, check_same_thread=False)
    permitidas = {sqlite3.SQLITE_SELECT, sqlite3.SQLITE_READ, sqlite3.SQLITE_FUNCTION}
    con.set_authorizer(lambda accion, *_: sqlite3.SQLITE_OK if accion in permitidas else sqlite3.SQLITE_DENY)
    return con

DB_PATH = descargar_chinook()
```

::: {.callout-note icon=false}

En producción, el cliente LLM lanza el servidor MCP como subproceso y se comunica por stdin/stdout. Pero en un notebook de Colab, lanzar subprocesos es complejo. Llamar a las tools directamente produce exactamente el mismo resultado y nos permite centrarnos en lo importante: ver cómo el LLM decide qué tool usar.
